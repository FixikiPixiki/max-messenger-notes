# Варианты синхронизации

`dist/max-notes.js` умеет синхронизировать заметки между компьютерами через
любой сервер, который понимает простой протокол:

- `GET /` с заголовком `X-Sync-Token: <токен>` → возвращает текущий JSON
  `{ "notes": {...}, "updatedAt": 1234567890 }`
- `POST /` с тем же заголовком и телом того же формата → сохраняет его

Ниже — два готовых варианта такого сервера. GitHub может хранить их код, но
**не может сам их запускать** (GitHub Pages отдаёт только статические файлы,
без бэкенда) — сервер нужно развернуть в одном из мест ниже.

Если синхронизация не нужна — просто не трогайте эту папку, `dist/max-notes.js`
по умолчанию работает без неё.

## Сравнение

| | [`yandex-cloud-function/`](yandex-cloud-function) | [`local-server/`](local-server) |
|---|---|---|
| Где работает | Yandex Cloud (облако) | Один из ваших компьютеров |
| Нужна оплата/карта | Да, привязка платёжного аккаунта | Нет |
| Работает, когда все компьютеры выключены | Да | Нет — нужен запущенный «главный» ПК |
| Нужен интернет на "главном" компьютере | Да (для облака в целом) | Да (для туннеля наружу) |
| Сложность настройки | Средняя (IAM, сервисный аккаунт, бакет) | Средняя (Python + туннель) |
| Подходит, если | уже используете Yandex Cloud | нет платёжного аккаунта, но есть общая сеть/интернет |

## yandex-cloud-function/

Serverless-функция на Python, хранит один JSON-файл в Yandex Object Storage.
Инструкция по развёртыванию — в комментариях в начале `index.py`.

## local-server/

Небольшой сервер на чистом Python (без зависимостей), который держит один из
ваших компьютеров «главным» и хранит файл с заметками локально. Чтобы к нему
можно было обращаться с `https://web.max.ru` (браузер блокирует запросы с
https-страницы на обычный http), сервер нужно выставить наружу через
бесплатный туннель, например [Cloudflare Tunnel](https://github.com/cloudflare/cloudflared)
(`cloudflared tunnel --url http://localhost:8787`, без регистрации).
Инструкция — в комментариях в начале `local_server.py`.
